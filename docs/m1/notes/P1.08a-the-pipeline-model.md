## Summary

Tetera can now describe image processing as a recipe, a graph of nodes with typed ports in JSON, check it whole before it runs, and run it.
- **Validation reports every problem, each once,** saying where it is and what is wrong:
  - an unknown node or version, an unknown port or reference;
  - an input left unfed, or given twice;
  - mismatched types;
  - a cycle, named node by node in the order data flows;
  - missing or invalid parameters;
  - an output from nowhere.

  The broken recipe in `recipes/` gets six messages, one for each of its mistakes.
- **The executor** runs the nodes in topological order, each after those that feed it, and checks that each node gives what it declared.
- **The registry** holds nodes by stable id and version, and starts with `tetera.crop` and `tetera.statistics`.
- **[ADR-0012](../../adr/0012-the-pipeline-model.md)** records the model.

## What was built

- **`tetera-pipeline`,** a new crate in layer 3, where plan §6.2 placed it:

  - `plan`: `Plan::check` and `Plan::new`, each `Problem`, the order, and `Plan::run`;

  - `glue`: `tetera.crop` and `tetera.statistics`.
- **`recipes/`:** `crop-and-measure.json`, and `broken.json`, which has a mistake in each node.
- **The `recipe` example.**
- **No new dependencies:** `serde`, `serde_json` and `schemars` were already in the workspace.

## Design notes and deviations from the plan

- **A node is a factory; its step runs.** `Node::prepare` reads the parameters once, into the node's own struct, and gives a `Step`. The step then runs on one set of inputs after another, and keeps any state, such as temporal averaging's window in P1.08b. Validation prepares every node, so bad parameters are found before anything runs.
- **Parameters are checked by serde, not by a JSON Schema validator.** Each node reads its parameters into a struct with `deny_unknown_fields`, and `schemars` makes the schema from the same struct. The messages are serde's: ``missing field `height` ``, ``unknown field `offset`, expected `gain` ``. Serde doesn't give the path within nested parameters, but no stock node nests them.
- **Each input names its feed, on the node's side,** not in a separate list of edges. The reader refuses a key given twice, which JSON itself would allow: that is the spec's "input fed twice".
- **Every problem, each once.** A node whose registry lookup, parameters or feeds failed isn't checked further. A node fed by a failed one, or by a cycle, isn't type-checked against a type no one knows. So one mistake gives one message, and the list of messages is a list of fixes.
- **The order keeps the recipe's order for ties,** so runs are deterministic. A cycle's nodes are set aside once it is reported, so the nodes they feed are still ordered, and left unchecked.
- **Recipes give outputs only from nodes;** an output naming a recipe input is refused.
- **Values are kept until the run ends.** Freeing each when its last reader is done belongs with the residency work in P1.08c.

## Tests, and the mutants

- **24 tests,** in every build:
  - **ports:** what an open type accepts, what a following type becomes, the phrase and JSON for each type, and values' types;
  - **descriptors:** outputs' types from the inputs', and each unsound descriptor refused; parameters in serde's words, and their schema;
  - **recipes:** read and written back; JSON that makes no recipe, with where and why; a key given twice; the schema's fields;
  - **validation:** each kind of problem, in 16 recipes with their exact messages; a problem said once, not again downstream; all the problems as one error; the shipped recipes;
  - **running:** the order, ties kept in the recipe's order; a diamond, each node run once, its state kept between runs; the inputs checked; a node's own error; a node that gives what it didn't declare;
  - **the registry:** the stock nodes and the catalogue; the latest version by default; a node registered twice, or unsound;
  - **the glue nodes:** crop on each sample type, and its refusals; statistics on each, one row and several; each given the wrong value.
- **Broken on purpose,** as the spec asks: **the validator's type check** switched off. It failed three tests: each kind of problem, a problem said once, and the shipped recipes.
- **Mutants,** over the whole new crate: 167 tested, 134 caught, 1 missed, 31 unviable, and 1 timeout, where `&&` as `||` makes the ordering loop never end, which counts as caught.
  - **The one missed:** the pixels counted as width over height, not times. Every image in the statistics test was one row high, and a 2 × 3 image now catches it.
