## Summary

Tetera serves its virtual instrument over HTTP, on teta-wot v0.2.0, from a service that runs under systemd in WSL. The phase's *Done when* holds:

- **`system` and `simulation` serve their Thing Descriptions, and the OpenAPI document lists them,** each property and action, beside teta-wot's own routes.
- **The configuration's defaults hold:** an empty file is the defaults, and the shipped `configs/tetera.toml` is the defaults but for its catalogue's path. A bad configuration is refused with what is wrong, such as ``unknown field `prot`, expected `address` or `port` ``, and the binary exits with code 2.
- **Under systemd in WSL, the service restarts after it is killed:** as a user unit, killed with SIGKILL, it was active again 2 s later with a new PID. A clean stop shut it down gracefully, exit code 0, and it stayed down.
- **A browser on Windows reaches http://localhost:8310:** `/docs` answers 200 from Windows, with mirrored networking.

## How to try it

```bash
cargo run --release -p tetera-server
curl http://127.0.0.1:8310/system/platform
curl -X POST -H 'Content-Type: application/json' -d '{"seed": 8}' http://127.0.0.1:8310/simulation/load
```

Then <http://localhost:8310/docs> from Windows. `tetera-api`'s and `tetera-server`'s READMEs have the rest.

## Performance

- **The server starts in about 0.2 s,** the instrument's assembly included. The GPU's first frame makes its tiles then: 0.3 to 0.9 s.
- **`system`'s `platform` asks Windows for WSL's version once,** when the Thing starts: `wsl.exe --version` takes about 30 ms here.

## Design notes and deviations from the plan

- **The Things are served at the root** (`/system/`), as teta-wot and LabThings' clients expect, and the media plane will be under `/api/v1/` (ADR-0017).
- **The instrument is a service the Things find when they start,** not a field they are built with: teta-wot builds them by `Default`, and `Dep<Instrument>` reaches actions.
- **`tetera-server` depends on `tetera-api`, not on teta-wot:** `tetera-api` builds and serves the server (`Service`), so the binary sees no teta-wot type.
- **The configuration's table for logging is `[log]`,** as `tetera-log`'s docs named it.
- **Relative paths are from the configuration file's folder,** but the data root is from where the server runs (`./.tetera/`), and log files go in the data root.
- **The clock's rate is 1 or more:** a stepped clock needs a test to step it, and a slower clock has no use yet.
- **The camera's sensor defaults to `auto`:** the whole MIChrome 20 on the GPU, 912 × 608 on the CPU, where the full sensor takes seconds a frame.
- **An unloaded slide shows bare glass,** the light with its unevenness and vignetting, on both backends.
- **The unit runs as a dynamic user,** its data in `/var/lib/tetera` (ADR-0018). The agent tested it as a user unit, without `sudo`; the owner installs the system unit at Checkpoint C.
- **The spec's broken-on-purpose for P1.13, the stage alarm's error mapping,** belongs to P1.13b, with the stage. P1.13a's is the unit's restart on failure.

- **32 new tests:**

    - each Thing through teta-wot's in-process test client: `system`'s properties; the OpenAPI document and `/docs`; `simulation`'s load, refusal and unload; its imperfections;

  - **`tetera-server`, 10:**
    - the defaults; the shipped file; a file that names only what it changes; bad configurations refused with what is wrong; `configs/tetera.toml` found or not;
    - the command line's overrides;

- **Broken on purpose,** as the phase's spec says: **the unit's restart on failure.** With `Restart=no`, the service killed with SIGKILL stayed failed (`Result=signal`, no restarts), and nothing answered on 8310. With `Restart=on-failure` restored, it came back.
- **Run 15 times,** with `tetera-sim` and `tetera-compute`, the tests passed each time.
- **Mutants:**
  - **the first run missed 11:**
    - WSL's version, now tested against what `wsl.exe` says;
    - the GPU's VRAM budget, untested without the `cuda` feature: a GPU test of the instrument now;
    - `Roots::settings`, `Service`'s debug output, and `Service::serve`: tests of their own, the last on a real port;
    - the binary's `main`, now run as a subprocess;
    - `Config::find`'s search for `configs/tetera.toml`, now `find_in` a folder;
    - the bare field's planes at a new size: a second sensor size through one cache.
  - **One test called the server's `run` in-process.** A mutant that skipped the configuration check made `run` serve on port 8310 until cargo-mutants' timeout stopped it. The binary's tests now run it as a subprocess, killed if it runs 30 s.
  - **The last runs missed none.**
