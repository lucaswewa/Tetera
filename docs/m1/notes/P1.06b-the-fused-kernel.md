# P1.06b: The fused kernel

- **Status:** In review
- **Branch:** `m1/p1.06b-the-fused-kernel`
- **Spec:** [phases.md](../phases.md#p106b-the-fused-kernel)
- **Size:** estimated 1,270 (code 660 · tests 500 · examples 80 · docs-as-code 20 · glue 10) → **measured 1,113** (code 495 · tests 566 · examples 47 · docs-as-code 3 · glue 2), **×0.88**

## Summary

The live view's whole chain now runs as one CUDA kernel: crop or bin, dark, flat, demosaic, resize, colour, to an 8-bit preview. It takes **4–5 ms from a full 20 MP frame to 1920 × 1280**, inside the plan's 10 ms. It matches the unfused chain **exactly**, over 60 random cases and from full frames, cropped and binned. The spec's tolerance, 1 level for 99.9 % of values and 2 for all, is measured and met with nothing to spare it for.

## What was built

- **`kernels/fused.cu`** (ADR-0011): one thread per preview pixel.
  - It walks its resize window.
  - At each tap it demosaics the pixel from sites it reduces, dark-subtracts and flat-fields as it reads them.
  - It applies colour once, to the resized value.
  - It uses the same integers as the unfused chain, in the same order.
- **`kernels/demosaic.cuh`:** the demosaic's sums, as templates over any source of sites, shared by `demosaic.cu` and `fused.cu`. `build.rs` inlines included headers into the source it embeds, since NVRTC compiles one string.
- **`tetera-compute`:**
  - `fused::FusedInputs`, and `CudaBackend::fused_isp`, which checks every buffer against the layouts, the crop or bin against the frame, the resize against the reduced size, and the method's minimum, then launches with one `#[repr(C)]` parameter struct;
  - `Reduce` and `MosaicLayout::reduced` move here from `tetera-imaging`, which re-exports them.
- **`tetera-imaging`:**
  - `Isp::run_fused`, the kernel on a GPU and the unfused chain on the CPU;
  - `DeviceIsp::run_fused`;
  - `compare_previews` and `PreviewDifference`, measured against the tolerance.
- **The `isp` example** times the fused kernel beside the chain, and checks it.
- **ADR-0011:** fused kernels.

## Performance

From `isp` in release, the best of 5, each including its output's allocation:

| | Unfused, CUDA | Fused |
|---|---|---|
| Full frame, 5472 × 3648, to 1920 × 1280 | 9.60 ms | **4.05 ms** (5.27 ms in an earlier run) |
| 2 × 2 binned in software, to 1920 × 1280 | 2.59 ms | 6.49 ms |

- **The budget,** 10 ms for 20 MP to 1920 × 1280 on the GPU (plan §6.15), is met with half of it to spare.
- **Binning in software inside the fused kernel is slower than unfused:** each tap averages four raw sites again for each site it reads. A camera's binned modes give frames already binned, which the fused kernel takes as a full frame, at that mode's smaller size. For software binning, the unfused chain is faster, and the pipeline engine (P1.08) can choose it.
- **The direct kernel needed no tiling.** ADR-0011 keeps shared-memory tiles as the next step, should a larger preview need them.

## Design notes and deviations from the plan

- **Exact, not within the tolerance:** every stage is integer arithmetic since P1.05a, so the fused kernel was written to compute the same integers in the same order. The tests ask for equality. `compare_previews` measures the spec's tolerance too, so an approximate kernel later would still be held to it.
- **Colour once per pixel,** as P1.06a's order lets it: the resize's sum is formed in linear light, then the matrix and the tables are applied once.
- **Zero weights are skipped:** they add nothing, so the sums are the same, and the window's padding costs no demosaicking.
- **Shared device code:** the demosaic's sums are templates over a source of sites, so the fused kernel's corrected mosaic and `demosaic.cu`'s plain one use the same code. A header needs `build.rs` to inline it for NVRTC; `nvcc` finds it beside the kernel.
- **One parameter struct:** sixteen values travel as one `#[repr(C)]` struct by value, its `DeviceRepr` impl unsafe with its reason.
- **`Reduce` and `MosaicLayout::reduced` moved to `tetera-compute`,** since the launch must check a crop or bin itself.

## Tests, and the mutants

- **9 new tests:**
  - **in `tetera-compute`:** 1 in every build, 4 on the GPU. `tetera-compute` now has 35 tests without the feature, and 71 with it;
  - **in `tetera-imaging`:** 2 in every build, 2 on the GPU. It now has 68 and 78.
  - **The equivalence:**
    - 60 random cases: sizes, patterns, offsets and vignetting, a full frame, an odd crop or a bin by 2 to 4, a dark and a flat or not, either method, random white balance, matrices and levels, previews smaller and larger;
    - and from a full 20 MP frame: whole, binned, and cropped at an odd offset.

    All identical to the unfused chain.
  - **The launch:**
    - a flat grey frame through each correction, the dark's clamp at zero among them;
    - the method asked for being the method used, by a bright site's hand-computed colour;
    - crops and bins reading the right sites;
    - every input that doesn't fit refused.
  - **Reducing,** in `tetera-compute` itself: crops moving the pattern, bins by the mean, crops outside the frame refused.
  - **Comparing previews:** the largest difference, the share within one level, the tolerance's edges.
- **Broken on purpose,** as the spec asks: the fused kernel with its flat field left out failed both equivalence tests. The random one was off by up to 6 levels, with only 36 % of values within one.
- **Mutants,** on both builds, over this phase's changes:
  - **`tetera-imaging`:** 35 tested with CUDA, 18 caught, 17 unviable, none missed. Without the feature, the 7 missed are code only the CUDA build compiles;
  - **`tetera-compute`, the first run with CUDA, missed 4:**
    - the launch's minimum-size check, which no test reached with only the height too small;
    - the method passed to the kernel, which flat frames can't tell;
    - and two the new launch tests already caught.

    Tests were added for each. The fused launch's 28 mutants are now 27 caught, 1 unviable;
  - **without the feature,** `MosaicLayout::reduced` was tested only from `tetera-imaging`. It has its own test now;
  - **a fix to the tests themselves:** cargo-mutants skips `#[cfg(test)]` modules, but not `#[cfg(all(test, feature = "cuda"))]`, so it had mutated test helpers. Both such modules are now `#[cfg(test)]` with the feature inside.

## Follow-ups and known gaps

- **Tiles through shared memory,** if a larger preview or a slower GPU needs them (ADR-0011).
- **Choosing fused or unfused:** the pipeline engine (P1.08) runs the fused kernel when a recipe matches the standard chain from a camera frame, and the unfused chain for software binning, where it is faster.
- **Device buffers kept between frames:** the preview pipeline (P1.14a).
