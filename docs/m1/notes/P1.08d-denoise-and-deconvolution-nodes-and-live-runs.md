## Summary

Every stock node is now in the registry, and recipes run live.
- **Three nodes:** `tetera.temporal_mean`, `tetera.bilateral` and `tetera.richardson_lucy`, each matching the function it wraps. Temporal averaging and the bilateral filter run on either backend, on the GPU giving exactly what they give on the CPU.
- **Live mode never queues more than one frame,** as the phase's *Done when* asks. A frame offered while one runs waits; a frame offered while one waits takes its place; so the next to run is always the latest.
- **The live chain runs live at 14.5 fps:** from a synthetic camera at 14.5 fps, 29 frames of 20 MP, on CUDA every frame runs, node by node or fused; on the CPU, about half give way to a later one.

## What was built

- **`restore`** in `tetera-pipeline`:
  - `tetera.temporal_mean`: stateful, its window kept on each backend, a new layout starting it again;
  - `tetera.bilateral`: on either backend, its tables uploaded once;
  - `tetera.richardson_lucy`: its PSF made once, from the optics in its parameters (NA, wavelength, pixel size, refractive index); any grey image in, floats out.
- **`live`:**
  - `Live::start`: a plan on a thread of its own, its frame's input given and the rest held;
  - `Live::offer`: the frame to run next, in place of any waiting; refused if it is the wrong type;
  - `LiveStats`: frames offered, run, given way, and dropped at the stop;
  - `Live::is_idle`, and `Live::stop`, which gives the plan back.
- **The stock module's helpers,** shared with the new nodes.
- **The `recipe` example** runs the live chain live, after one frame to start, on the CPU, on CUDA node by node, and fused.
- **No new dependencies.**

## Design notes and deviations from the plan

- **One slot, not a queue.** The live thread runs one frame; one more can wait. A frame offered while one waits takes its place, and is counted as having given way. So a slow recipe always runs the newest frame, and memory holds at most two frames in flight.
- **A live run gives its frame alone;** every other input must be held, so the masters are uploaded and their steps worked once, as P1.08c made them.
- **Stopping** lets the frame running finish, drops the one waiting, and gives the plan back, so it can be run again or inspected.
- **Results go to a callback on the live thread:** the caller chooses a channel, a frame bus (P1.14a), or a counter.
- **Richardson–Lucy takes its image on the host.** `tetera-imaging` deconvolves it on the GPU when there is one, with copies of its own, which the plan's count doesn't include. Taking a device image would need `DeviceDeconvolution` to start from one; deconvolution isn't part of the live chain.
- **Temporal averaging isn't told of stage moves yet:** the node passes no move, and starts again only for a new layout. The preview pipeline, which knows when the stage moves, wires that (P1.14a).
- **Live tests are deterministic.** A test node runs a frame only when the test hands it a token, so what waits, what gives way and what runs never depend on timing. Run 30 times, the tests passed 30 times.

## Tests, and the mutants

- **10 new tests,** 9 in every build and 1 on the GPU. `tetera-pipeline` now has 46 without the feature, and 52 with it:
  - **temporal averaging** against `TemporalMean`, frame by frame, its window kept; windows refused;
  - **the bilateral filter** against its function; bad σs and wrong images refused;
  - **Richardson–Lucy** against `richardson_lucy_cpu`, from `u8`, `u16` and `f32` images, with total variation and a medium's index; bad iterations, weights, optics and images refused;
  - **live:** frames offered while one runs give way, the first and the latest running; frames offered after each run all run, and an error comes back as an error; a frame waiting at the stop is dropped; dropping a live run stops its thread; a frame of the wrong type refused; a live run's inputs given and held as it needs;
  - **on the GPU,** temporal averaging over six frames and the bilateral filter, each what it gives on the CPU;
  - and the registry holding every stock node.
- **Broken on purpose,** as the spec asks: **live mode keeping every frame,** in a queue. It failed the test of frames giving way to the latest.
- **Mutants,** with CUDA and without, over this phase's changes: 43 tested each way, 28 caught, 11 unviable, 2 timeouts (a live run started where it shouldn't, which never ends), and the same 2 missed:
  - **`is_idle`'s two conditions,** one of them redundant: the counts alone say no frame runs or waits, and the other is gone;
  - **dropping a live run without stopping its thread:** a test now sees the thread end, its callback's channel closing.

  The second run, over `Live`: 26 tested, 21 caught, 3 unviable, 2 timeouts, none missed. The live tests, run 20 more times, passed each time.
